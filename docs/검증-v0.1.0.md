# v0.1.0 검증 범위

검증일: 2026-10-18. 실제 Claude Code가 제품 소스를 수정했고, Codex가 별도로 빌드하고 실행 결과를 검수했습니다.

## 공개 실행 파일 검증

공개용 소스에서 Windows x64 자체 런타임 포함 단일 EXE를 게시했습니다. 디버그 심볼을 제외하고, EXE 한 개만 새 폴더로 복사한 상태에서 아래 검사를 실행했습니다.

| 검사 | 결과 |
| --- | --- |
| .NET 10 SDK Release 게시 | 성공 |
| 자체 검사 | 56/56 통과 |
| 실제 MainForm GUI 검사 | 15단계 통과 |
| 트레이 시작 검사 | 감시 ON/OFF 모두 통과 |
| 기존 사용자 창 | 검사 전후 12개 창의 위치·크기·복원 좌표·표시 상태 동일 |
| 시험 창 이외의 창 이동 | GUI 검사 범위 위반 0건 |
| 앱 이름 | 창 제목·트레이·파일 제품 정보에 창자리 (WindowDock) 반영 |

GUI 검사에서는 자체 생성한 시험 창만 사용했습니다. 실제 적용 버튼, 트레이 배치 적용, 일시정지·시작·열기·숨기기·종료, 배치 업데이트의 취소·승인·파일 잠금 실패·닫힌 항목 보존을 확인했습니다. 업데이트 확인 응답은 테스트에서 주입하지만 버튼 처리와 파일 저장 경로는 실제 코드를 실행합니다.

트레이 시작 검사는 실제 WinForms 창·트레이·타이머와 테스트용 창 제공자를 함께 사용합니다. 숨김 상태에서 창이 나타나지 않는지, 기존 창 이동이 0회인지, 새 일치 창의 이동이 1회인지, 이미 사용 중인 자리를 다른 창이 차지하지 않는지 확인했습니다. 따라서 이 검사를 모든 실제 프로그램의 동작 증거로 보지는 않습니다.

개인 경로와 창 제목을 제외한 결과 요약은 [verification-v0.1.0.json](verification-v0.1.0.json)에 있습니다.

## 기존 기능 검증

이 공개 버전에서는 직전 검증본의 표시 이름과 제품 정보만 변경했습니다. 창 매칭·이동·감시·저장·시작 동작은 변경하지 않았습니다. 앞선 기능 검수에서는 다음을 확인했습니다.

- 512개 매칭 그래프의 1,536개 판정과 별도의 후보 부족·독립 역할 반례.
- 숨겨진 창의 자리 유지, 제목 조건 편집 등 6개 서비스 재현 사례.
- 손상된 배치 거부, 설정 백업, 파일 잠금 시 정확한 실패 반환 등 실제 EXE의 CLI 4개 사례.
- 자체 생성한 Win32 시험 창의 좌표 복원, 최소화·최대화, 수동 이동 유지 등 23개 항목.
- 작업 스케줄러에 등록한 로그인 시작 명령을 현재 사용자 환경에서 직접 실행해 트레이 시작 확인.

이전 원본 검수 파일에는 개인 창 제목·실행 경로가 포함될 수 있어 공개 저장소에는 올리지 않았습니다.

## 확인하지 못한 범위

- 실제 PC 재부팅·로그오프는 수행하지 않았습니다. 등록된 로그인 명령의 직접 실행으로 확인했습니다.
- 실제 검증 화면은 물리 모니터 1대, 5120×1440입니다. 여러 물리 모니터와 혼합 DPI 환경은 추가 검증이 필요합니다.
- 관리자 권한 앱을 포함한 모든 외부 프로그램의 제어를 보장하지 않습니다.
- Windows의 포커스 제한 때문에 별도 창을 강제로 전면에 두는 한 가지 관찰은 성립하지 않았고, 통과 항목에 포함하지 않았습니다.

## 검사 명령

Windows의 대화형 데스크톱에서 실행합니다. `--ui-smoke`와 `--native-smoke`는 자체 시험 창을 잠깐 열고 이동·종료하므로 순서대로 실행하세요. 일반 사용자 배치에 `--apply-profile`을 실행하는 방식의 검사는 하지 않습니다.

PowerShell에서 경로를 실제 압축 해제 폴더로 바꾼 뒤 실행합니다.

```powershell
$exe = (Resolve-Path .\WindowLayoutManager.exe).Path
$checks = Join-Path (Get-Location) ('checks-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $checks | Out-Null

$p = Start-Process -FilePath $exe -WindowStyle Hidden -Wait -PassThru -ArgumentList @(
  '--self-test', '--output', ('"' + (Join-Path $checks 'self.json') + '"')
)
if ($p.ExitCode -ne 0) { throw 'Self-test failed' }

$p = Start-Process -FilePath $exe -WindowStyle Hidden -Wait -PassThru -ArgumentList @(
  '--tray-start-smoke', '--output', ('"' + (Join-Path $checks 'tray.json') + '"')
)
if ($p.ExitCode -ne 0) { throw 'Tray smoke failed' }

$p = Start-Process -FilePath $exe -WindowStyle Hidden -Wait -PassThru -ArgumentList @(
  '--ui-smoke', ('"' + (Join-Path $checks 'ui.png') + '"'),
  '--data-dir', ('"' + (Join-Path $checks 'ui-data') + '"'),
  '--output', ('"' + (Join-Path $checks 'ui.json') + '"')
)
if ($p.ExitCode -ne 0) { throw 'UI smoke failed' }
```

추가 실제 시험 창 검사는 같은 방식으로 `--native-smoke --output <JSON 경로> --data-dir <새 시험 폴더>`를 전달합니다. 검사 결과 파일은 창 경로나 시스템 정보를 포함할 수 있으므로 공개 전 내용을 확인하세요.
