# v0.3.0 검증 기록

검증 환경: Ubuntu 24.04 x64, X11, Mutter. Linux 실행부를 추가했으며 Windows 제품 코드는 버전 번호만 변경했습니다.

| 검사 | 범위 |
| --- | --- |
| Linux 자동 검사 | 35개 통과. 매칭·경계 입력·실파일 저장·감시·WM 거절 판정·설치기·동일 경로 인스턴스 |
| Linux native / UI | GNOME Shell 및 별도 Xvfb/Openbox에서 각각 21/21 통과. 실제 GTK 시험 창 이동·크기·최대화·재열기·적용·슬롯·감시 정지·중복 실행 |
| 설치 | 사용자 폴더 설치·재설치·공백 있는 경로·실행·제거 시 개인 데이터 보존 통과 |
| 현재 PC 실행 | 설치된 앱 창 표시, 중복 실행 0 종료, 개인 배치 0개 기본 상태 확인 |
| 독립 코드 검토 | 최대화 거절 오보고·과도한 JSON 중첩·동일 폴더 중복 인스턴스 지적 3건 수정, 각각 회귀 검사 통과 |
| CI | [Windows/Linux 워크플로 실행 결과](https://github.com/Choi-sungjin/WindowDock/actions/workflows/build.yml)에서 별도 확인 |

로컬 실행 명령과 결과:

```text
PYTHONPATH=linux /usr/bin/python3 -m unittest discover -s linux/tests -p 'test_*.py' -q
Ran 35 tests — OK

PYTHONPATH=linux /usr/bin/python3 linux/tests/native_smoke.py --output artifacts/checks/linux-native.json --screenshot artifacts/checks/linux-ui.png
{"total": 21, "passed": 21}

./linux/install.sh
~/.local/bin/windowdock --version
0.3.0
```

실제 통합 검사 화면은 [Linux 검사 화면](images/windowdock-linux.png)에 있습니다. UUID로 표시한 일회용 시험 창만 사용했습니다. 자동 검사 결과는 특정 시험 입력 범위에 대한 증거입니다.

Openbox에서 최대화 해제 직후 발생하는 창 테두리만큼의 위치 오차를 재현하고 처리했습니다. 정확히 테두리 크기와 일치하는 오차일 때만 1픽셀 이동 후 원래 목표로 복원하며, 최종 위치가 다르면 실패로 처리합니다. 통합 검사는 Wnck의 관찰값 외에 X 서버에서 창 외곽 위치를 별도로 읽어 목표 좌표를 확인합니다.

## 범위 밖

- 실제 사용자 앱 전체에 대한 호환성, 로그인/재부팅 자동 실행, Wayland, Linux 전역 단축키.
- 물리 모니터 분리·연결, 혼합 DPI 전환. 음수 좌표·사라진 모니터 영역 처리는 모델 검사입니다.
- UI 버튼 검사는 코드에서 GTK 버튼 신호를 발생시켰습니다. 실제 마우스·키보드 입력 검사로 세지 않습니다.
- 트레이는 Ayatana typelib과 상태 아이콘 지원 데스크톱이 있을 때만 활성화됩니다.
- 기존 Windows 실제 데스크톱 검증은 v0.2.0 기록입니다. v0.3.0의 Windows CI 빌드·자체 검사는 새로운 실제 Windows 데스크톱 사용 검증을 뜻하지 않습니다.
